# 어드민 UI 개선 (라벨 · 툴팁 · 퍼널 카드) — 2026-08-06

민재님·혜원님께서 주신 티켓 3건에 대한 반영 계획과, 티켓에 제시된 숫자에 대한 확인 결과입니다.

## 1. 요청 사항 및 상태

| # | 요청 | 반영 내용 | 상태 |
|---|---|---|---|
| ① | 탭·카드 명칭 변경 | `전체 (99)` → `참여 세션 (99)`, `로그인 현황` → `접속/명단 현황` | 반영 예정 |
| ② | `?` 도움말 툴팁 추가 | 세션 수 / 로그인 수 각각의 집계 기준 설명 | 반영 예정 |
| ③ | 상단 퍼널 요약 카드 | 전체 접속자 → 응답 시작 → 미응답/이탈 | 반영 예정 |

---

## 2. 변경되는 문구

**라벨**

- 세션 목록 탭: `전체 (99)` → **`참여 세션 (99)`**
- 카드 제목: `로그인 현황` → **`접속/명단 현황`**

**툴팁 (`?` 아이콘 클릭 시)**

- 참여 세션: **"질문 응답을 1개 이상 작성하여 세션이 생성된 유저 수"**
- 접속/명단 현황: **"사이트에 1회 이상 로그인한 전체 유저 수 및 차수별 명단"**

---

## 3. 퍼널 카드의 계산 기준

세 숫자를 모두 **현재 선택된 차수 탭** 하나에서 파생시킵니다.

| 항목 | 정의 |
|---|---|
| 전체 접속자 | 선택된 차수 기간에 로그인한 인원 |
| 응답 시작 | 그중 응답을 1개 이상 작성해 세션이 생성된 인원 |
| 미응답/이탈 | 전체 접속자 − 응답 시작 |

**이 기준을 택한 이유**
서로 다른 기간·서로 다른 집계 단위의 숫자를 빼면 뺄셈 자체가 성립하지 않습니다.
세 숫자를 같은 차수 탭에서 함께 계산하면 기준이 하나로 고정되므로, 탭을 어디로
바꾸셔도 `접속자 − 응답 = 미응답` 관계가 항상 맞습니다.

---

## 4. ⚠️ 티켓에 제시된 숫자(159 → 99 → 60)는 그대로 쓰기 어렵습니다

죄송하지만 해당 수치는 실제 참여 현황을 과장·왜곡해 보여줍니다. 이유는 두 가지입니다.

**(1) 세션 99건에는 개발 테스트 기록 31건이 포함되어 있습니다**
6/30~7/14 사이에 생성된 개발·검증용 기록으로, 세션명이 `test`, `neo`, `probe`, `abc`
등입니다. 7/16 행사의 실제 참가자 세션은 **68건**입니다.

**(2) 로그인 수는 사람 단위가 아니라 브라우저 단위입니다**
한 분이 휴대폰과 노트북으로 접속하면 2로 집계됩니다. (탑승자명 기준으로 묶는 개선은
이미 배포되었으나, 배포 이후 생성된 기록에만 적용됩니다.)

따라서 `159 − 99 = 60`은 **기준이 다른 두 숫자를 뺀 값**이라 의미를 부여하기 어렵습니다.

**4차 행사 기간 기준 정확한 수치**

| 구분 | 인원 |
|---|---|
| 전체 접속 | **141** |
| 응답 시작(세션 생성) | **68** |
| 미응답 | **73** |

퍼널 카드는 3항의 방식(선택된 차수 탭 기준 단일 산출)으로 구현하므로 이 문제를
구조적으로 피합니다.

---

## 5. 대기 중인 결정 사항 — `사전 테스트` 차수 등록

테스트 기록 31건에 대한 근본적인 정리 방안으로, 앞서 제안드리고 아직 회신을 기다리고
있는 건입니다.

**제안**: 테스트 기간(6/1~7/15)을 **`사전 테스트`**라는 별도 차수로 등록합니다.
데이터를 삭제하지 않고 **재분류**하는 방식이므로 **되돌리기 가능**하며, **재배포도
필요하지 않습니다**.

**적용 전후 (응답 기준)**

| 차수 | 현재 | 적용 후 |
|---|---|---|
| MVP 4차 | 58 | **59** |
| 사전 테스트 | — | **31** |
| 미지정 | 40 | **9** |

세션 99건 중 31건이 6/30~7/14에 생성된 개발 테스트 기록이고, 로그인 수는 사람이 아니라
브라우저 단위로 집계되어 두 숫자의 기준이 서로 다르기 때문입니다. 4차 행사 기간만 놓고
보면 **접속 141 → 응답 시작 68 → 미응답 73**이 정확한 값이며, 퍼널 카드는 선택하신 차수
탭을 기준으로 세 숫자를 함께 계산하도록 구현하여 기준이 어긋나지 않게 하겠습니다.

이와 관련해 앞서 드린 제안에 대한 결정을 부탁드립니다. 테스트 기간(6/1~7/15)을
`사전 테스트` 차수로 등록하면 테스트 기록 31건이 본 행사 통계에서 분리됩니다.
삭제가 아닌 재분류라 언제든 되돌릴 수 있고 재배포도 필요하지 않습니다.
적용 시 응답 기준으로 MVP 4차 59 / 사전 테스트 31 / 미지정 9가 됩니다.
퍼널 카드 오픈 시점부터 정확한 숫자가 보이도록, 회신 주시면 함께 반영하겠습니다.
